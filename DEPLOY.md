# Деплой: Vercel Hobby + Neon Free

Всичко се вписва в безплатните тарифи. Стъпките с регистрации и пароли трябва да
минат през теб — там има акаунти и тайни, които не бива да пипа никой друг.

## 1. Качи кода в GitHub и го свържи с Vercel

1. Направи хранилище в GitHub и качи проекта.
2. Във [vercel.com](https://vercel.com) → **Add New → Project** → избери хранилището
   → **Deploy**.

Първият деплой ще се получи, но сайтът още няма да работи — няма база. Това е
нормално, оправя се в следващата стъпка.

## 2. Създай базата ОТ Vercel (тук се получава връзката)

Не създавай Neon акаунт отделно и не копирай никакви адреси. Vercel има готова
интеграция, която прави базата и **сама попълва променливите в проекта**:

1. В проекта във Vercel отвори таба **Storage**.
2. **Create Database** → **Neon** (Serverless Postgres).
3. В прозорчето: приеми условията, избери регион (**Frankfurt / eu-central-1** е
   най-близо), план **Free**, и дай име на базата.
4. Накрая избери за кои среди да важи — маркирай **Production**, **Preview** и
   **Development** — и натисни **Connect**.

Това е всичко. Vercel сам добавя в проекта, наред с други:

| променлива | какво е |
|---|---|
| `DATABASE_URL` | адресът **през pooler** — това ползва сайтът |
| `DATABASE_URL_UNPOOLED` | **директният** адрес — това ползват миграциите |

Кодът чете точно `DATABASE_URL`, така че от твоя страна няма какво да се пипа.

<details>
<summary>Ако вече имаш Neon акаунт и предпочиташ ръчно</summary>

В Neon Console натисни **Connect**, избери branch и база. Там има ключе
**Connection pooling**: включено дава адрес с `-pooler` в хоста, изключено — без
него. Сложи ги на ръка във Vercel като `DATABASE_URL` (с pooler) и
`DATABASE_URL_UNPOOLED` (без).

</details>

**Защо два адреса.** Всяка заявка към сайта може да вдигне нов екземпляр на
функцията във Vercel и всеки отваря свои връзки. Pooler-ът приема до 10 000
клиента и ги свежда до няколко истински връзки; без него при повече хора
едновременно базата почва да отказва нови връзки. Обратно, pooler-ът работи в
„transaction mode" и не поддържа неща на ниво сесия (`SET`, временни таблици,
`PREPARE`), които drizzle-kit ползва — затова
[миграциите искат директния адрес](https://neon.com/docs/connect/connection-pooling).

## 3. Останалите променливи

Project → **Settings → Environment Variables**, за средите Production и Preview:

| име | стойност |
|---|---|
| `CRON_SECRET` | генерирай с `openssl rand -hex 32` |
| `SCHEDULE_URL` | `https://bulgarian-football.com/elitna-grupa-u17.html` |
| `SCRAPER_CONTACT` | твоят имейл — влиза в User-Agent на скрейпъра |
| `SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASS`, `SMTP_FROM` | изпращане на линкове за нова парола (виж стъпка 6) |

`DATABASE_URL` НЕ се добавя тук — Neon интеграцията вече го е сложила.

## 4. Миграции срещу Neon

Базата, която Vercel е създал, е **празна**. Два начина да ѝ се създадат таблиците
— избери според това дали искаш да пипаш терминал.

### Вариант А: от браузъра, през Neon (без терминал)

1. Във Vercel → **Storage** → щракни базата → бутонът **Open in Neon**.
2. В Neon Console отвори **SQL Editor**.
3. Отвори файла [`drizzle/bootstrap.sql`](drizzle/bootstrap.sql), копирай цялото
   съдържание, постави го в редактора и натисни **Run**.

Файлът създава 12-те таблици и записва миграциите като приложени, така че
по-нататъшен `drizzle-kit migrate` продължава оттам, вместо да опитва същото пак.

Пресъздава се с `npm run db:bootstrap-sql`, ако някога се добави нова миграция.

### Вариант Б: от терминал

```bash
export NVM_DIR="$HOME/.nvm"; . "$NVM_DIR/nvm.sh"; nvm use 24

npx vercel login
npx vercel link    # свързва папката с проекта във Vercel
```

После една команда. `vercel env run` подава променливите на Vercel направо на
командата, без да ги записва във файл:

```bash
npx vercel env run -e production -- \
  sh -c 'DATABASE_URL="$DATABASE_URL_UNPOOLED" npx drizzle-kit migrate'
```

`DATABASE_URL="$DATABASE_URL_UNPOOLED"` подменя адреса с директния само за тази
команда — drizzle-kit чете `DATABASE_URL`, а pooler-ът не става за миграции.

Провери, че е минало:

```bash
npx vercel env run -e production -- \
  sh -c 'psql "$DATABASE_URL_UNPOOLED" -c "\dt"'
```

Трябва да излязат 12 таблици.

<details>
<summary>Ако `vercel env run` не е наличен в твоята версия на CLI</summary>

```bash
npx vercel env pull .env.vercel --environment=production   # НЕ пипа локалния .env
DATABASE_URL="$(grep '^DATABASE_URL_UNPOOLED=' .env.vercel | cut -d= -f2- | tr -d '"')" \
  npx drizzle-kit migrate
```

Внимание: без `--environment=production` командата дърпа средата **development**,
която може да няма тези променливи. `.env.vercel` съдържа боеви достъп — той е в
`.gitignore`, изтрий го, като приключиш.

</details>

Същото се повтаря при всяка нова миграция.

## 5. Деплойни отново

В проекта във Vercel → **Deployments** → на последния деплой **⋯ → Redeploy**.
Първият деплой беше без база; този вече ще тръгне.

### Кронът

`vercel.json` вече го описва:

```json
{ "crons": [{ "path": "/api/cron/refresh", "schedule": "0 4 * * *" }] }
```

04:00 UTC ≈ 07:00 българско време. Vercel Hobby позволява **само веднъж дневно** и
изпълнява в рамките на посочения час, не на минутата. Vercel сам подава
`Authorization: Bearer $CRON_SECRET`.

Понеже кронът е един на ден, а резултатите излизат в неделя вечер, бутонът
„Обнови от източника" в админ панела е основният механизъм, не резервният.

## 6. Изпращане на имейл

Нужно е само за линковете „забравена парола". Кодът говори SMTP, така че всеки
доставчик става — избери си по това дали имаш собствен домейн:

| | безплатно | иска ли домейн | бележка |
|---|---|---|---|
| **Brevo** | 300 писма/ден | **не** — стига да потвърдиш един адрес подател | най-лесното без домейн |
| **Gmail** | да | не | иска включена 2FA и App Password, не обикновената парола |
| **SendGrid** | 100 писма/ден | не — има потвърждаване на единичен подател | |
| **Resend** | 3000/месец | **да** | без домейн праща само до собствения ти адрес — не става за група |

Каквото и да избереш, попълваш същите пет променливи:

```
SMTP_HOST=smtp-relay.brevo.com
SMTP_PORT=587
SMTP_USER=<от доставчика>
SMTP_PASS=<от доставчика>
SMTP_FROM=Прогнози U-17 <твоят-потвърден-адрес>
```

Ако ги оставиш празни, сайтът работи, но „забравена парола" няма да може да
изпрати нищо в продукция — тогава остава админският линк от панела.

Провери, като поискаш линк за собствения си профил от `/forgot`.

## 7. Първи админ

Пак от твоята машина, по същия начин като миграциите:

```bash
ADMIN_EMAIL=ти@example.com ADMIN_PASSWORD='<твоя парола>' \
  npx vercel env run -e production -- \
  sh -c 'DATABASE_URL="$DATABASE_URL_UNPOOLED" npx tsx scripts/seed-admin.ts'
```

Паролата я избираш ти и остава само при теб — скриптът не измисля пароли.

## 8. Първо напълване на графика

Влез като админ и натисни „Обнови от източника". Трябва да покаже 120 видени мача.

## 9. Проверка след деплой

```bash
# трябва 401
curl -s -o /dev/null -w "%{http_code}\n" https://<домейн>/api/cron/refresh

# трябва 200
curl -s -H "Authorization: Bearer $CRON_SECRET" https://<домейн>/api/cron/refresh
```

После в админ панела виж дали обходът е записан като `success`.

## Какво да следиш

- **Структурата на източника.** Ако страницата се промени, парсърът хвърля грешка с
  ясно съобщение и обходът се записва като `error` в админ панела — не се записват
  половин данни. Тогава: свали новия HTML в `test/fixtures/`, оправи парсъра, пусни
  тестовете.
- **Втори полусезон.** Кръгове 16–30 вероятно ще са на друг URL. Схемата го поема
  (`rounds.number` не е ограничен), но ще искат втори fixture и втори `SCHEDULE_URL`.
- **Ръчно въведени резултати.** Обновяването ги презаписва: източникът е истината.
  Ако въведеш полувреме, което той не публикува, следващият обход ще го изчисти —
  затова замрази кръга от админ панела веднага след като го въведеш.
